## Полная версия

## Задача

Проанализируй проект [moeru-ai/airi](https://github.com/moeru-ai/airi/tree/main) и спроектируй **полную иерархию таблиц БД для AI-cards** — конфигурируемых AI-компаньонов для стриминга.

### Контекст моего проекта (Chimera)

- **Продукт**: Платформа для настройки и конфигурирования нейросетевых образов (AI-компаньонов) для стриминга. Пользователи меняют промты, алгоритмы и модели ИИ, чтобы создать уникального напарника для своих стримов.
- **Целевая аудитория**: Стримеры, геймеры, контент-креаторы, организаторы online-событий.
- **Функционал**:
  - Модули для изменения логики взаимодействия (промты, сценарии)
  - Инструменты кастомизации внешнего вида и поведения ИИ
  - API для интеграции с Twitch, YouTube, Discord
  - Подписки (месячные/годовые), разовые покупки моделей/расширений

### Текущее состояние

- **apps/web**: React + Vite frontend, аутентификация через **Keycloak** (OAuth).
- **БД**: PostgreSQL, пока **только таблица Users** (id, email, passwordHash, displayName, googleId, twitchId, role, isActive, createdAt, updatedAt).
- **Связь User ↔ Keycloak**: `User.Id` или `sub` из Keycloak token — идентификатор пользователя в моей системе.
- **Бэкенд**: .NET 10, модули Identify (auth), Synapse (обработка чат-сообщений), Soul (будущая логика AI-персонажей).

### Референс: проект AIRI

AIRI — self-hosted AI companion (VTuber/waifu), аналог Neuro-sama. Изучи его структуру:

- **bucket/airi.json** — метаданные приложения
- **packages/stage-ui** — stores/modules (оркестрация AI), providers
- **packages/stage-shared** — общая логика
- **Memory**: DuckDB WASM, pglite, Memory Alaya (RAG)
- **Концепции**: character/waifu как «контейнер души», промты, голос (ElevenLabs), внешний вид (VRM, Live2D), модули, провайдеры LLM

Обрати внимание на:
- Как организованы **провайдеры** (LLM, TTS, STT)
- Как хранятся **промты** и **сценарии**
- Как устроена **память** и контекст
- Связь **character → modules → providers**

### Что нужно от тебя

Спроектируй **иерархию таблиц** для хранения AI-cards у пользователей. AI-card — это полная конфигурация одного AI-компаньона: промты, модель, голос, внешний вид, логика, интеграции.

**Ограничения:**
- Только структура — без миграций и кода
- PostgreSQL
- Пользователь уже есть (Users), связь через `user_id` (FK)
- Учитывай мультитенантность (один пользователь — много AI-cards)
- Учитывай будущее: тарифы, подписки, marketplace моделей/расширений

**Формат ответа:**
1. **ER-диаграмма** (текстом, mermaid или описание связей)
2. **Список таблиц** с полями, типами, FK, индексами
3. **Краткое обоснование** ключевых решений
4. **Рекомендации** по нормализации, денормализации, JSONB для гибких полей

### Дополнительные требования

- Поддержка **версионирования** конфигураций (история изменений промтов/настроек)
- Возможность **шаринга** AI-card (публичный/приватный, шаблоны для сообщества)
- Разделение **глобального каталога** (модели, голоса, ассеты) и **пользовательских настроек**
- Учёт **лимитов по тарифам** (количество AI-cards, моделей, и т.п.)
